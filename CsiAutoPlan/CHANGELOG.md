# Change log

One entry per deployed change. Code changes get a new `<ScriptVersion>` (script name `AutoPlanv<version>.esapi.dll`);
Up to 1.6, config-only changes were listed as "config"; since 1.7 every setting is in the code, so every change is a version. Record review / approval and the test patients used.

| Version | Date | Change | Reviewed / approved | Test patients |
|---|---|---|---|---|
| 1.7 | 2026-10-26 | **Production layout.** (1) **No settings file**: all site settings moved from `CsiAutoPlan.config.xml` into `SiteSettings.cs` (rooms, geometry, plan, fields, range margins, robust optimization, objectives, HU rules), compiled in and covered by Script Approval; the settings model has no default values. Values identical to 1.6 (compared field by field). The config search, template / harvested XML files and `CSI_AUTOPLAN_CONFIG` are gone; tab 5 lists the IDs of existing proton plans as lines for `SiteSettings.cs`; `room_summary.py` prints `SiteSettings.cs` lines. (2) **Range margins**: each field's proximal / distal target margin = (R − SOBP) × 3.5 % + 3 mm / R × 3.5 % + 3 mm (PBSTV margin sheet), with R and SOBP from Eclipse (`NominalRange`, `NominalSOBPWidth`, read with zero margins; beam line calculated once if Eclipse has no values yet), rounded up to 0.1 mm; fields without usable values keep the fixed 0.5 cm margins and get a checklist item; tab-3 box to switch it off per patient; tab 5 shows R / SOBP and the sheet margins of existing fields. (3) Unit tests and offline harness moved to a separate verification package (`CsiAutoPlan-verification`), not part of the plugin folder. Checked: harness, 22 situations, identical to 1.6 with range margins off; formula checked against the six margin-sheet rows. **To confirm on the non-clinical system:** Eclipse's R / SOBP equal the values used for the margin sheet. | | |
| 1.6 | 2026-10-26 | **All structure settings in one file, `StructureRecipes.cs`**: input names (BODY, AI brain / thecal sac, involved VBs, CTV and couch patterns), PBSTV margins, crop to BODY, INV_VB crop, one OPT per spine field, the field codes used in IDs (`BR`, `UP`, `LOW`, ...), and every structure the plugin creates (ID, DICOM type, how it is built) as a list of recipes; the rest of the script finds them by role. Removed from the config: `<Structures>`, `<BrainPbstvMargins>`, `<SpinePbstvMargins>`, `<InvolvedVb>`, `<CropFieldTargetsToBody>`, `<BodyCropInsetMm>` (an old config still loads; the log lists the ignored elements). Recipes are checked at start (duplicate IDs, missing `{F}`, roles); a failing recipe is named in the log. Structures you add appear in the DVH summary. Offline harness: `--vb` adds an involved-VB structure; it checks the recipes first. `CHANGING-STRUCTURES.md` rewritten for the new file (examples compiled against ESAPI and run in the harness). Proton 3 enabled (`Proton_3-Table` confirmed) with the P1/P4/P5 layout `PostBrain`. Checked: 21 offline-harness variants (incl. `--vb`) give the same structures, fields and objectives as 1.5 (only log wording / order differs), except Proton 3, which changes layout as intended (with `--post-extended` it matches 1.5 exactly). | | |
